Overview

This dashboard provides static HTML pages for testing the SlotWise backend API.

🔐 Authentication

Test user registration, login, and logout. Authentication uses HTTP-only cookies.

POST /api/v1/auth/register
POST /api/v1/auth/login
DELETE /api/v1/auth/logout
Go to Auth Testing

🛠️ Services

Test service CRUD operations. Providers can create, read, update, and delete their services.

GET /api/v1/service/my-services
GET /api/v1/service/:id
POST /api/v1/service/
PATCH /api/v1/service/:id
DELETE /api/v1/service/:id
Go to Services Testing

🔗 Quick API Reference

Method Endpoint Auth Required Description
POST /api/v1/auth/register No Register a new user
POST /api/v1/auth/login No Login and get auth cookie
DELETE /api/v1/auth/logout No Logout and clear cookie
GET /api/v1/service/all-services No Get all services
GET /api/v1/service/my-services Yes (provider) Get provider's own services
GET /api/v1/service/:id No Get service by ID
POST /api/v1/service/ Yes (provider) Create a new service
PATCH /api/v1/service/:id Yes (provider) Update a service
DELETE /api/v1/service/:id Yes (provider) Delete a service
GET /api/v1/availability/availability No Get available slots for a provider
GET /api/v1/availability/ Yes (provider) Get provider's availability settings
POST /api/v1/availability/ Yes (provider) Set provider availability
POST /api/v1/availability/exception Yes (provider) Add availability exception
DELETE /api/v1/availability/exception/:id Yes (provider) Delete availability exception
POST /api/v1/booking/request Yes (user) Request a booking
GET /api/v1/booking/me Yes (user) Get customer's appointments
GET /api/v1/booking/provider/requests Yes (provider) Get provider's pending requests
PATCH /api/v1/booking/:id/approve Yes (provider) Approve appointment
PATCH /api/v1/booking/:id/reject Yes (provider) Reject appointment
PATCH /api/v1/booking/:id/cancel Yes (user) Cancel appointment
